# API contract types — recorded debt (Nov 6 2026)

**Decision (Kevin: "pick best for my POS"):** accept a new baseline, keep the ratchet.

`check:api-contract` part 7 (TYPED) requires every route to name an `@aipowersalon/api-contracts` request/response type in
its handler signature, or be listed in `apps/api/openapi/route-types.baseline.txt`, a list that only shrinks. Between the
Oct 8 freeze and Nov 6, 845 routes were built without a wire type, so the gate was red on every run and stopped catching
new untyped routes.

Why not type all 845 now: typing a route means writing and reviewing a request and response type for each one. Doing that
for 845 routes in one pass would touch the controllers behind 88 route groups (see below) and their frontend API clients at once. The risk of
breaking working screens is real, and the gain does not change behaviour for any salon. The routes are already
validated at the edge (`ValidatedBody` schemas, the reachable / keyed / domain / gated checks) — this is about the
typed client contract, not input safety.

What was done:
- The 845 routes were added to the baseline (3548 untyped, 386 of 3934 typed). The header records why.
- The gate is green again, and every NEW untyped route fails it. Typing a route and re-running
  `--write-types-baseline` removes its line, so the baseline still only shrinks.
- Paying it down: type a module's routes when that module is next changed (its controller + its client together).
  Largest groups are listed below.
