 Non-negotiable product boundary
 SUPER ADMIN REMAINS ENGLISH-ONLY. Tenant-facing POS users may switch between English and Tiếng Việt. A tenant
 Owner/Admin may set the salon default language, while each user can override that default for their own POS session/profile.



 Primary UX requirement
 Language switching changes presentation only. It must not log the user out, refresh the page, reset a booking, reorder Fair

 • Tenant-facing AI PowerSalon POS: bilingual English + Vietnamese.
 • Super Admin: English only.

 • Future languages may be added later, but production scope now is only en and vi.

1. Inspect Existing Localization Code First
Scan the entire monorepo before installing or introducing a new i18n library. Find existing translation resources, locale utilities,
language selectors, formatters, localized templates, and hard-coded English user-facing strings.
Classify every existing implementation as KEEP, FIX, MERGE, COMPLETE, MIGRATE, or REMOVE. Do not create a second competing
localization system.
 • Search React/TSX/JSX, shared UI packages, API error contracts, validation schemas, receipts, customer display, communication
   templates, and POS navigation.
 • Identify any locale behavior already present in mobile apps or shared packages and reuse it where appropriate.


2. Application Scope
Fully localize tenant-facing POS surfaces and all shared tenant-facing components they use.
 • Overview; Live Operations; Check-In; Booking; Tech Queue; Customer Queue; Serving; Service Done; Checkout.
 • Customers; Memberships; Team; Services & Products; Payments & Money; Communications; Marketing & Growth; AI Center;
   Reports; Management; Devices & Integrations; Account; Settings.
 • Dialogs, drawers, modals, notifications, validation, errors, charts, tooltips, empty states, status pills, Quick Actions, and
   confirmation messages.


3. Super Admin Is English-Only
Do not translate the Super Admin application. Do not add a Vietnamese language toggle to Super Admin. Its navigation, tenant
management, billing, merchant management, audit, security, support, analytics, and operational tooling remain English.
Super Admin may expose English-labeled controls such as Default POS Language: English / Vietnamese, because it manages
tenant configuration while staying English itself.

4. Tenant Language Must Never Affect Super Admin
A tenant with Vietnamese as its POS default must still appear in English when opened from Super Admin.


5. Tenant POS Language Selector
Add a clean language selector to the tenant-facing POS top bar or the existing user/account area without breaking header density.
 • Recommended display: English / Tiếng Việt, optionally with a globe icon.
 • The control must be keyboard accessible and touch friendly.
 • The selected locale must be immediately visible to the current user.


6. Language Switching Must Be Immediate
Switch English to Vietnamese and Vietnamese to English without logout, browser reload, app restart, or route reset.

 change locale -> rerender translated strings -> preserve route/state -> persist user preference




7. Do Not Reset Operational State During Language Change
Language is presentation state. It must not alter domain state.
 • Do not lose selected customer, ticket, appointment, branch, Booking date, Booking technician page, queue selection,
   modal/form data, payment intent, realtime state, or filter state.
 • Do not trigger duplicate payment API calls or duplicate websocket subscriptions.


8. Locale Resolution Hierarchy
Resolve locale in this order: explicit user preference, then tenant default, then English fallback.

 user.locale ?? tenant.defaultLocale ?? "en"




9. Tenant Default POS Language
Tenant Owner/Admin should be able to set the salon default POS language in tenant settings, ideally under Account -> Settings ->
Language & Region or the closest existing configuration area.


10. Tenant Default Does Not Force Every User
A salon can default to Vietnamese while one receptionist or owner uses English. A personal preference overrides the salon default.


11. Top-Bar Switch Changes the Current User
Changing language from the normal POS selector updates only the current user preference. It must not mutate
tenant.defaultLocale.


12. Changing Salon Default Is a Separate Administrative Action
Tenant Owner/Admin changes the default language through settings with the appropriate permission. This is separate from My
Display Language.


13. Recommended Persistence Model
Use the existing settings/preferences architecture where available. Do not persist language only in localStorage.

 tenant_settings
  tenant_id
  default_locale

14. Locale Validation
Backend must validate locale values against the supported set. Reject arbitrary locale strings.

 SUPPORTED_LOCALES = { "en", "vi" }




15. localStorage Is Cache Only
Browser storage may cache the most recent locale for startup performance, but server/user preference remains the durable
authority.


16. Language Is Not Authorization
Changing locale must never affect role, permission, tenant, branch, employee identity, payment authority, or manager approval
logic.


17. Recommended Frontend Architecture
If a mature localization library already exists, keep and finish it. If none exists, use one standard React i18n solution such as
i18next + react-i18next or the project-standard equivalent.


18. Shared Localization Package
Centralize configuration, translation resources, locale resolution, formatting helpers, and namespaces in a shared package that
tenant-facing apps can reuse.

 packages/i18n/src/
  config
  locale-resolver
  formatters
  namespaces
  translations/en/...
  translations/vi/...
