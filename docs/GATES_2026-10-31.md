# Repo gates — full run, 31 Oct 2026

What was run: every `check:*` script in `apps/api/package.json` (61; the root package.json has none), each with
`cd apps/api && npm run -s <name>`, plus the same scripts that need module resolution through the repo's stand-in loader
(`node --experimental-strip-types --import tooling/full-system-test/unit-standin/register.mjs apps/api/scripts/<script>`).
Environment: cloud workspace, PostgreSQL 16 `aps` template migrated through 738, **no node_modules** (registry unreachable).

**Correction to earlier reports.** The Global Loyalty evidence (G1 row) and the Segments / Coupons / Deals reports said
"all gates rc 0", but only 14 of the 61 `check:*` gates were run then. This full run found 5 real failures introduced by
that work; they are fixed in the commit that adds this file:

| Gate | Was failing because | Fix |
|---|---|---|
| `check:dead-client` | `posCustomersApi.bySegment`, `posDealsApi.listKind` lost their callers in the Segments / Deals rebuilds | deleted (and the test mock entry) |
| `check:list-queries` | `SegmentsController.members` built its sorts with `Object.fromEntries(...)` — not statically evaluable | literal sorts object, type-checked against `SEGMENT_SORTS` |
| `check:sql:select` | `retention-snapshots.ts` reused alias `p` (payments) for `customer_loyalty_profiles` in a lateral subquery, so `p.ticket_id` resolved against the wrong table | lateral alias renamed `clp` (the query itself was valid SQL; now unambiguous) |
| `check:async-exports` | `GET /super-admin/loyalty-network/books-check/findings.csv` was not on the async export contract | `@AsyncExport({ kind: 'super-admin.loyalty-network.findings-export', estimate: { table: 'rewards_recon_findings', platform: true } })`; the Super Admin client uses `api.exportAsync(…, 'text')` |
| `check:audit-writers` | 5 raw `INSERT INTO audit_logs` in loyalty (`global-rewards.repository.ts`, `global-rewards.service.ts`, `rewards-books-check.ts`) | new `recordPlatformAuditStrict(trx, actor, input)` in `modules/audit` (fail-closed, same row shape and metadata redaction as `AuditService.recordPlatform`, written on the caller's transaction); action names unchanged (`loyalty.<action>`) |

Also stale and regenerated: `docs/EVENT_CATALOG.md` (the loyalty consumer of `checkout.completed` / `payment.refunded` was
never listed), the openapi manifest and the attack-surface docs (the new async marker).
